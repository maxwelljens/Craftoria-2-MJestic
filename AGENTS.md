# AGENTS.md

Guidance for AI agents (and humans) working in this repository.

## What this repository is

This is **Craftoria 2: MJestic**, a fork of TeamAOF's Craftoria 2 — a
[packwiz](https://packwiz.infra.link/)-managed NeoForge modpack. It is not a
software project. There is no application code to build or run; the repo *is*
the pack, declared as:

- mod metadata (packwiz `.pw.toml` files — never commit mod `.jar`s),
- mod configs, quest data, and KubeJS scripts,
- a generated index (`index.toml`) that hashes every pack file.

Naming conventions (don't mix these up when renaming anything):

- **Display name**: `Craftoria 2: MJestic` — used in the main menu, window
  title, quest book title, crash reports, and release tooling output.
- **Slug**: `craftoria-2-mjestic` — used in `pack.toml`, `bcc-common.json`,
  and the automation settings; mirrors the GitHub repo name.
- **The `craftoria:` KubeJS namespace is deliberately NOT renamed.** It is an
  internal identifier wired into quest icons, tags (`craftoria:mob_blacklist`)
  and textures; renaming it would break quest data for no visible gain.

Target versions live in `pack.toml` (Minecraft `26.1.2`, NeoForge
`26.1.2.97` as of v0.11.0). All content changes are edits to declarative
files, verified by keeping the packwiz index consistent — not by compiling
anything.

## Layout

| Path | Contents |
|---|---|
| `mods/` | Packwiz metafiles, one `.pw.toml` per mod (CurseForge metadata mode) |
| `resourcepacks/`, `shaderpacks/` | Same, for packs; zips are downloaded at install time |
| `pack.toml`, `index.toml` | Pack manifest; generated file index (hashes) |
| `config/` | Mod configs — **indexed into the pack** |
| `defaultconfigs/` | Configs copied for new worlds |
| `kubejs/` | KubeJS scripts (`startup_scripts/`, `server_scripts/`, `client_scripts/`) and quest assets under `assets/ftbquests/` |
| `config/ftbquests/quests/` | FTB Quests book: `chapters/`, `lang/en_us/`, `reward_tables/`, `chapter_groups.json5` |
| `automation/` | Bun changelog generator + Windows PowerShell CurseForge uploader |
| `changelogs/` | Generated release history — **never hand-edit** |
| `server_files/` | Standalone server bootstrap kit (Java 25) |
| `notes/` | Developer notes |
| `InstanceSync.jar`, `version_info.json` | Client-side auto-updater payload |

`.packwizignore` is a **whitelist**: everything is excluded except
`config/`, `defaultconfigs/`, `kubejs/`, `mods/`, `resourcepacks/`,
`shaderpacks/`, `emotes/` (whitelisted but currently absent), and
`version_info.json`. Repo-only folders
(`automation/`, `changelogs/`, `notes/`, `server_files/`, `MODLIST.md`) are
not part of the exported pack.

## The golden rule: packwiz refresh

Every change to a pack file (anything indexed: configs, KubeJS, quest data,
mod metafiles) **must end with a packwiz index refresh**:

```sh
packwiz refresh          # run from the repo root
```

This updates per-file hashes in `index.toml` and the index hash in
`pack.toml`, prunes deleted files, and adds new ones. Packwiz is not
vendored; install it with
`go install github.com/packwiz/packwiz@latest` or grab a release binary.

Notes from experience:

- `refresh` also **fixes case-mismatched paths** (e.g. quest chapters are
  stored on disk as `Occultism.json5` but were once indexed lowercase) and
  will rewrite stale hashes committed by upstream. A noisy index diff after
  refresh usually means the index was already out of sync — let it happen.
- Do not hand-edit `index.toml`; run the tool.

## Adding a mod

1. Create `mods/<slug>.pw.toml` following the existing convention:

   ```toml
   name = "Display Name"
   filename = "exact-jar-filename.jar"
   side = "both"

   [download]
   hash-format = "sha1"
   hash = "<sha1 of the jar>"
   mode = "metadata:curseforge"

   [update]
   [update.curseforge]
   file-id = <file id>
   project-id = <project id>
   ```

   All mods in this pack use CurseForge metadata mode; keep it consistent.
   The hash must be of the exact jar you are pinning.
2. Run `packwiz refresh`.
3. **Sync the two bookkeeping files** (they are not generated by packwiz):
   - `MODLIST.md` — one bullet per mod: `  * [filename.jar](CF file URL) (by [author](member URL))`
   - `config/crash_assistant/modlist.json` — one JSON entry keyed by jar
     filename with `modId`, `name`, `version`, `curseForgeHash`,
     `modrinthHash`. **This file has a UTF-8 BOM** — preserve it.
4. If the mod needs configs or a KubeJS integration, add them under
   `config/` / `kubejs/` and refresh again.

## Removing a mod

Removing a mod is a checklist, not a deletion. Cross-wiring points observed
in this pack (see `notes/removal-theurgy-occultism.md` for a complete worked
example):

1. `mods/<slug>.pw.toml` and the mod's own `config/<modid>-*.toml` files.
2. Shared library mods that become orphans — verify with **two** checks:
   - grep `config/` and `kubejs/` for the mod id (finds *content* references);
   - check every remaining mod's **declared jar dependencies**
     (`neoforge.mods.toml` inside the jar, or the CurseForge/Modrinth
     dependency listing). A library with zero grep hits can still be
     hard-required — this pack keeps Modonomicon solely because Neo Vitae
     declares `type="required"` on it, which is invisible to grep.
3. FTB Quests: chapter(s), their lang file(s), titles in
   `lang/en_us/chapter.json5`, reward tables and their titles, chapter groups
   (if the group becomes empty), theme sections in
   `kubejs/assets/ftbquests/ftb_quests_theme.txt`, and title textures under
   `kubejs/assets/ftbquests/textures/gui/`. Quest dependencies are raw hex
   GUIDs that can cross chapters — extract the removed quests' IDs and grep
   the remaining chapters before deleting.
4. `kubejs/server_scripts/tags.js` (entity/item tag entries).
5. `config/neovitae/materials.json` — dynamic materials that `smelt_to`
   removed-mod items.
6. `config/reskillable/skill_locks.json` — skill locks on removed items.
7. `config/jade/jade.json` + `profiles/*/jade.json` + `sort-order.json`.
8. `config/jei/recipe-category-sort-order.ini` and
   `config/jei/ingredient-list-mod-sort-order.ini`.
9. `config/sound_physics_remastered/sound_rates.properties` (namespaced
   lines, `modid\:sound=-1`).
10. `config/titanium/titanium-tags.toml` (`ITEM_PREFERENCE` list).
11. `config/jei_biome/biome_blocks.json` — machine-generated, ~150k lines,
    strict JSON; scrub removed block ids with a script, not by hand.
12. Bookkeeping: `MODLIST.md`, `config/crash_assistant/modlist.json`.
13. `packwiz refresh`.

Leave `changelogs/` untouched — they are release history. Some references
are auto-regenerated by mods at runtime (e.g. Apotheosis
`name_generation.cfg` comments) and can be ignored.

## FTB Quests conventions

- Chapter and lang files are **JSON5**: unquoted keys and trailing commas
  are normal; don't parse them with strict JSON tooling.
- Everything is correlated by raw hex GUIDs: a chapter's `id`, its
  `filename`, its lang keys (`chapter.<GUID>.title`), and its theme section
  (`[<GUID>]` in `ftb_quests_theme.txt`) must stay in sync.
- Quest text lives in `lang/en_us/chapters/<Name>.json5` keyed by
  quest/task GUIDs; chapter titles live in `lang/en_us/chapter.json5`.
- Textures for quests go in `kubejs/assets/ftbquests/textures/` and are
  referenced as `ftbquests:` assets.
- Chapter groups are defined in `chapter_groups.json5` with titles in
  `lang/en_us/chapter_group.json5`; empty groups are kept intentionally as
  placeholders for planned chapters.
- `data.json5` sets global quest book behaviour (e.g.
  `progression_mode: linear`).

## File-format gotchas

- `config/jei_biome/biome_blocks.json`: huge, generated, strict JSON, **no
  trailing newline** — script edits only; verify with `jq empty` afterwards.
- `config/crash_assistant/modlist.json`: UTF-8 BOM (parse with
  `utf-8-sig`).
- `config/jei/world/local/...`: committed dev-world JEI lookup history;
  harmless, unknown ingredients are dropped by JEI. Don't add more of these.
- KubeJS assets folder doubles as a resource pack: textures referenced from
  quest JSON must exist under `kubejs/assets/ftbquests/`.

## Dimension mods (knowledge from the Nov 2026 experiment)

An `experiment-01` branch (kept on origin, never released) prototyped adding
**The Undergarden** and **Voidscape** as v0.12.0; the decision was made not to
ship it, but the knowledge is preserved in `notes/adding-dimension-mods.md`
(playbook, file checklist, mod gotchas, cheat-test protocol) and
`notes/research-dimension-mods-neoforge-26.1.md` (cited version-availability
research). Before any dimension-mod work, read both. High-value facts:

- **Version matrix (Nov 2026):** The Undergarden 0.9.8 and Voidscape 1.11.660
  have NeoForge 26.1.2 builds; Deeper and Darker (max NeoForge 1.21.1,
  `neoforge-26.1` port in progress) and Cracker's Wither Storm (1.20.1) do
  not. Compat addons are stuck on 1.21.1.
- **Progression spine:** Apotheosis World Tiers (advancement-unlocked,
  manually activated via CTRL+T, global difficulty) + Reskillable skill locks
  (`config/reskillable/skill_locks.json`, ladder 3→50). New dimension gear
  must be threaded into that ladder and Neo Vitae's
  `config/neovitae/materials.json`, or the dimension becomes a sidequest.
- **Dimension-id registration:** waystones allowlist, Xaero cave-mode lists,
  Discord RPC matchers, JEI sort order need explicit entries. Xaero's
  `cave_mode_allowed_dimensions` is an *allowlist* (empty = cave mode
  everywhere) — a lone modded-dimension entry disables cave mode elsewhere.
- **FTB Quests chapter backgrounds** are set in
  `kubejs/assets/ftbquests/ftb_quests_theme.txt` per `[<GUID>]` section
  (`background: ftbquests:textures/gui/<file>.png; color=#a0a0a0`), not in the
  chapter file; chapter `image:` fields are canvas decorations / quest images.
- **`crash_assistant/modlist.json`:** `curseForgeHash` is CurseForge's
  Murmur2 fingerprint (whitespace-skipping) and `modrinthHash` is the SHA-1 of
  the installed jar — both computable locally; keep the UTF-8 BOM.
- **Voidscape's void is intentionally pitch-black** (Voidic Visibility
  attribute gates the lightmap; its armor sets raise it). Torches "not
  working" there is the mod's design, not a compatibility bug.

## Commits and changelogs

- Use **Conventional Commits**. Only `feat` and `fix` commits appear in the
  generated changelog; scopes `dev` and `dx` are excluded. Descriptions
  must start with an imperative verb ("add", "remove", "bump").
- The changelog generator
  (`automation/scripts`, run `bun generate-changelog` or
  `bun src/generate-changelog.js`) diffs commits since the last release and
  writes `changelogs/changelog_mods_<version>.md`. It detects the cutoff by
  finding a commit literally named **`version bump X.Y.Z`** (or a semver
  tag) — bump the version in `pack.toml` and commit with exactly that
  message before generating a changelog, or the script will warn.
- Bun is required for the scripts; no `node_modules` needed.
- CurseForge release packaging is Windows PowerShell:
  `automation/modpack-uploader.ps1` with `settings.ps1` (keep
  `$MODPACK_VERSION` in sync with `pack.toml`; the CF token belongs in
  untracked `secrets.ps1`).

## Verification checklist for pack changes

There is no compile step; verify changes statically:

1. `packwiz refresh` ran cleanly and `git diff index.toml` shows only
   intended entries (deleted files pruned, new files added).
2. Every edited JSON parses (`python3 -m json.tool` or `jq empty`); JSON5
   quest files pass a JSON5-aware check.
3. `grep -ri "<removed mod id>" config/ kubejs/ mods/` returns only
   intentionally-kept hits (changelogs, auto-regenerated comments).
4. Cross-reference GUIDs you touched: quest IDs, chapter IDs, reward table
   IDs, theme section IDs.
5. `MODLIST.md` and `config/crash_assistant/modlist.json` match the contents
   of `mods/`.
